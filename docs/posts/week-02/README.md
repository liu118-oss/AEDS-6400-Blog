# Blog Post 2: Technical skills in Arbeitnow job postings

## Research question

Among software, data, and IT postings in a large snapshot of Arbeitnow, which named technical skills appear most often? How do the patterns differ across remote and other roles, and what should a job seeker study next?

## Folder structure

- `code/01_scrape_jobs.R`: collect 100 public HTML listing pages with `rvest`, load the public API feed, and save cleaned jobs.
- `code/extend_api_cache.R`: helper sourced by the collector; paginate the public API at a controlled pace until it ends or 1,000 technology roles are available.
- `code/02_analyze_jobs.R`: define technology roles, clean and count named skills, compare remote roles, and make figures and tables.
- `data/raw/html/`: saved HTML page snapshots.
- `data/raw/api/`: saved public API responses.
- `data/processed/`: cleaned HTML listings, API jobs, technology jobs, and skill mentions.
- `results/`: all summary tables and the figure generated by the analysis script.
- `index.qmd`: blog article; `index.html`: rendered article.

## Replication

From the repository root, install packages once and run:

```sh
Rscript -e 'install.packages(c("rvest", "dplyr", "readr", "jsonlite", "stringr", "tidyr", "ggplot2", "knitr"))'
Rscript posts/week-02/code/01_scrape_jobs.R
Rscript posts/week-02/code/02_analyze_jobs.R
quarto render posts/week-02/index.qmd
```

The collector reuses saved raw pages, so repeating the analysis does not make new requests. To collect a new snapshot, remove `data/raw/` and rerun the first script. HTML pages are requested sequentially with a 1.25-second pause; API requests use an 8-second pause. The API reduces the need to request thousands of individual job pages. The collector stops when the API returns an empty final page. If the site returns HTTP 429, stop and wait for its rate limit to reset; do not work around it. Raw caches are ignored by Git because they are large; the processed data and results are the reproducible snapshot for the repository.

## Source and interpretation

Arbeitnow: [public job listings](https://www.arbeitnow.com/), [documented public API](https://www.arbeitnow.com/blog/job-board-api), [robots.txt](https://www.arbeitnow.com/robots.txt), and [API terms](https://www.arbeitnow.com/terms). The terms request a link back, which this post provides. The website is focused on Germany and has postings in German and English. The HTML and API are separate snapshots of the same job board; the analysis uses API descriptions and records whether each URL also appears in the HTML sample. Neither sample is a random sample of all jobs.

The September 21 collection yielded 5,000 unique HTML listings and 1,019 technology-related titles. The public API ended at page 30 and supplied 3,153 unique descriptions; 543 matched the technology-title rule. Of those 543, 341 also appeared in the 100-page HTML snapshot. The description-based skill table uses **543 roles**. The separate title-based table covers all 1,019 technology-related HTML titles but captures only technologies explicitly named in titles. Do not treat its lower counts as the full list of requested skills.

Technology roles are identified by a documented title pattern in `02_analyze_jobs.R`. Skill counts use a fixed dictionary and indicate **mentions in a posting**, not necessarily strict requirements. A company may repeat the same description across openings. The analysis reports the full API sample, the technology subset, and the HTML/API overlap so readers can see the denominator used for each percentage.

The API's `remote = FALSE` value is reported as **not marked remote**. It does not establish that a job is fully in person; hybrid and unspecified arrangements may be present. Seniority is inferred from title terms, and jobs without those terms are labeled **No level stated**. The script saves work-mode counts and remote shares by role in `results/`.
